# 《硅与海》产品需求文档（PRD）

## 1. 背景与问题

目标行业（具身智能/机器人、智能硬件出海）的动态分散在两类渠道：海外英文渠道（公司 Newsroom、arXiv、英文科技媒体）与国内渠道（中国厂商官网、官方微博微信、交易所及招投标平台、产业链消息）。两侧都不可偏废，因此本产品不设语言门槛，也不把「是否一手」当作准入门槛，而是按出处可信度分级标注（详见 §5 信源规则 v0.5）。人工追踪存在三个痛点：

1. **时间成本高**：每天 1–2 小时刷源筛选阅读；
2. **覆盖不全**：依赖平台算法推送，融资、新品、量产节点、论文、政策类关键事件容易漏；
3. **出处难核**：事件在媒体之间层层转述，数字与时间点容易漂移，必须回到当事方原文才算数。

**量化目标**：把每日行业信息获取成本从约 120 分钟压缩到 10 分钟以内；重要事件漏报率通过评测集（§9）持续度量并下降。

## 2. 目标用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 具身智能 / 出海硬件方向的求职者、从业者、观察者 | 每天跟踪行业动态，建立并更新行业认知 | 快、全、出处可追溯 |

**使用场景**：每天早上花 10 分钟读完前 24 小时全球行业动态。

## 3. 产品定位与差异化

**一句话定位**：每条标注出处与可信度、附一句话点评的具身智能与出海硬件中文日报。

与市面泛 AI 日报/自媒体的差异：

1. **出处分级标注**：A 官方 / B 媒体 / C 未证实 三级都收，但每条必须标明它能被信到什么程度（§5 v0.5）；不设语言门槛，中英文同权；
2. **窄切口**：具身智能 + 智能硬件出海两条线，不做泛 AI；
3. **每条带点评**：一句「为什么重要」，AI 负责汇总，判断由人来把关；
4. **面向求职/入行场景**：单列「求职雷达」板块，聚焦行业头部公司动态。

## 4. 核心功能需求

### P0
- **F1 每日抓取**：按 `sources.md` 信源分级，每日 06:30 拉取近 24 小时更新（RSS 优先，无 RSS 的 Newsroom 页面抓取）；
- **F2 筛选与去重**：按 §5 入选标准过滤，跨信源去重，同一事件只保留出处级别最高的那条；
- **F3 摘要 + 点评 + 分级标注**：原文（中英文皆可）→ 中文摘要（≤80 字）+ 点评（≤50 字）+ 原文链接 + 出处级别标注（A/B/C，见 §5 v0.5）；
- **F4 日报生成**：按 §7 模板输出 markdown；
- **F5 人工终审与发布**：作者约 5 分钟审阅修订后发布。发布通道：企业微信群机器人（微信直达）→ 邮件备份 → 线上作品集站点同步。人机边界：AI 生成初稿，人对事实、数字、判断负最终责任。

### P1
周报汇总。

## 5. 入选标准（筛选规则）

**入选**：
- 融资/并购（金额 ≥ 千万美元级）；
- 头部公司新品发布、量产与交付节点；
- 关键技术突破（顶会论文、arXiv 高关注、实机演示视频）；
- 供应链与制造动态（代工、芯片、产能）；
- 行业头部公司（见 §6 重点跟踪公司清单）的任何动态；
- 行业政策、标准、展会重要公告。

**不入选**：无实质内容的融资八卦、营销软文、与硬件无关的纯软件模型发布、重复转发。

**阈值**：宁缺毋滥，单期 5–10 条；无合格内容则发布「今日空仓」——空仓本身也是诚实的信号。

**窗口规则**：主表坚持 24 小时窗口不变。另设「补漏区」：每期文末固定保留【前日回溯】板块，列出过去 24–72 小时内发生、但因超窗未入正报的重要条目，各附链接与一句话说明，最多 2 条。原则：正报只认 24h（纯度），补漏区负责兜底（不漏大事）。

**信源规则 v0.5**：

按出处可信度分三级，级级可收录，区别在于标注义务。

| 级别 | 定义 | 举例 | 标注要求 | 可否进头条 |
|---|---|---|---|---|
| **A 官方** | 当事方自行发布或公开存档记录 | 公司 Newsroom / 官网、官方微博与公众号、交易所与招投标公告、工商与专利、arXiv / GitHub、发布会回放 | 附原文链接即可 | ✅ |
| **B 媒体** | 有署名、有明确信源的专业媒体报道 | The Robot Report、TechCrunch、IEEE Spectrum、TechNode、EqualOcean、36氪、量子位、澎湃、OFweek | 必须写明**媒体名 + 发布时间** | ✅ |
| **C 未证实** | 产业链消息、供应链传闻、未获当事方回应的消息 | 「产业链称」「据知情人士」类 | 必须写「**未经官方证实 / 未获当事方回应**」，且不得以肯定语气陈述 | ❌ 只进快讯或前日回溯 |

执行要点：
1. 同一事件存在多个级别时，优先采用级别最高的出处；
2. 不得把 C 级消息写成事实陈述，**这是唯一不可越过的底线**；
3. 每条摘要末尾按上表补齐标注，缺标注视为不合格，退回重写。

## 6. 信息源策略

明细见 `sources.md`，分三级抓取：

- **T1 每日必抓**（8–10 个，RSS 优先）：行业媒体 + 论文 + 头部科技媒体；
- **T2 每日/隔日扫读**：重点跟踪公司的 Newsroom 页面抓取；
- **T3 每周复盘**：市场研究机构、launch 平台、周更栏目。

抓取层级（T1/T2/T3，管的是「多久抓一次」）与出处可信度分级（A/B/C，管的是「能不能信、怎么标注」）是两套独立维度，不要混用。任何一层抓到的条目，都要先按 §5 v0.5 判定 A/B/C 级别再决定标注方式。

**信源不设语言门槛**：中国厂商的一手发布多为中文，与英文源同权；是否可信由级别（A/B/C）决定，不由语言决定。

**重点跟踪公司清单**（T2 抓取优先级来源；覆盖两个方向的行业头部公司）：
- 出海智能硬件：Anker 安克、影石 Insta360、韶音 Shokz、绿联、倍思、未来智能（讯飞 AI 耳机）
- 机器人：优必选、普渡、越疆、乐聚、众擎、星尘智能、逐际动力、宇树、智元

## 7. 日报格式规范（输出模板）

```markdown
# 硅与海 | YYYY-MM-DD（第 N 期）

## 头条（1–2 条）
- 中文标题（≤25 字）
- 摘要（≤80 字）+ 点评「为什么重要」（≤50 字）+ 原文链接

## 快讯（5–8 条）
- 一句话事实 + 一句点评 + 链接

## 求职雷达
- 行业头部公司动态单独列出（哪家的什么岗位值得留意）

## 前日回溯（补漏区，最多 2 条）
- 过去 24–72 小时内超窗但重要的条目：标题 + 链接 + 一句话说明

> 公开日报只含以上四节正文。数据看板、筛选全记录、T2 基线快照与信源健康记录属内部运行数据，存放于私有目录，不对外发布。日报正文不附「本报由 AI 生成初稿」声明。
```

## 8. 系统架构（MVP）

```
抓取层（RSS / Newsroom 页面）
   → 筛选层（规则过滤 + LLM 逐条判断入选/待审/剔除）
   → 生成层（LLM 翻译、摘要、点评）
   → 输出层（markdown 归档 digests/）
   → 推送层（企业微信 webhook → 邮件备份 → 站点同步）
```

## 9. 评测方案

| 指标 | 定义 | 度量方式 |
|---|---|---|
| 漏报率 | 该报而未报的重要事件占比 | 每周对照 T1 信源当周全量头条人工标注 golden set |
| 误报率 | 发布后判定不该入选的条目占比 | 期后复盘标记 |
| 时效 | 事件发生 → 入报的时间差 | 抽样记录 |
| 质量 | 摘要准确性、点评含金量 | 作者 5 分制评分 + 读者反馈 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 信源失效/改版 | 每周源健康检查，失败计数自动标记 |
| 信息噪音大 | 阈值收紧，宁缺毋滥，空仓照发 |
| 生成幻觉（错译/编造数字） | 人工终审 + 关键数字必须回链核对 |
| 版权风险 | 只摘要 + 链接，不搬运全文图片 |
| 断更 | 自动化兜底；断更超 2 天在日报中如实说明 |
