# 硅与海 · Silicon & Sea

**一条「每条都能点开验证」的具身智能 × 智能硬件出海中文日报。**

线上站点：<https://silicon-sea.pages.dev/>

每天早上 10 分钟，读完过去 24 小时全球具身智能（人形机器人、灵巧手、具身大模型）与智能硬件出海方向的融资、新品、量产节点、论文与政策动态。每条都带原文链接、出处可信度分级和一句「为什么重要」。

---

## 为什么做这个

目标行业的信息散落在两类渠道：海外英文一手源（公司 Newsroom、arXiv、英文科技媒体）和国内一手源（厂商官网、官方微博微信、交易所与招投标公告）。人工追踪有三个真实痛点：

1. **时间成本高** —— 每天 1~2 小时刷源筛选；
2. **覆盖不全** —— 依赖平台算法推送，融资、量产节点、论文类关键事件容易漏；
3. **出处难核** —— 事件在媒体之间层层转述，数字与时间点容易漂移。

**量化目标**：把每日行业信息获取成本从约 120 分钟压缩到 10 分钟以内。

## 与泛 AI 日报的差异

| | 硅与海 | 市面泛 AI 日报 |
|---|---|---|
| 切口 | 只做具身智能 + 智能硬件出海两条线 | 泛 AI，什么都收 |
| 出处 | 每条标注 A/B/C 可信度分级 | 多数不标 |
| 语言 | 中文一手源与英文源同权 | 偏英文二手转述 |
| 每条内容 | 中文摘要 + 一句点评 + 原文链接 | 摘要，链接常缺失 |
| 面向场景 | 求职/入行的行业认知建立 | 泛资讯消费 |

### 信源可信度分级（v0.5）

| 级别 | 定义 | 举例 | 标注要求 |
|---|---|---|---|
| **A 官方** | 当事方自行发布或公开存档 | 公司 Newsroom / 官网、官方微博公众号、交易所与招投标公告、arXiv / GitHub | 附原文链接即可 |
| **B 媒体** | 有署名、有明确信源的专业媒体报道 | The Robot Report、TechCrunch、IEEE Spectrum、量子位、36氪 | 必须写明「媒体名 + 发布时间」 |
| **C 未证实** | 产业链消息、供应链传闻、未获当事方回应 | 「产业链称」「据知情人士」 | 必须写「未经官方证实」，且不得以肯定语气陈述；只进快讯，不进头条 |

> 底线：**不得把 C 级消息写成事实陈述。** 缺标注视为不合格，退回重写。

### 数据诚实性

- **宁缺毋滥**：单期 5~10 条，无合格内容就发「今日空仓」——空仓本身也是诚实的信号。
- **窗口规则**：正报只认 24 小时窗口（保证纯度），文末固定保留【前日回溯】板块兜底 24~72 小时内的漏网大事。
- **人机边界**：AI 负责抓取、去重、摘要、点评初稿；人对事实、数字、判断负最终责任。

## 自动化链路

整条流水线每个工作日 06:30 自动运行，无需人工触发：

```
信源抓取(T1/T2/T3)  →  筛选与跨源去重  →  摘要+点评+分级标注
        →  生成 markdown 日报（写入 ai-brief/digests/）
        →  更新 digests.json 索引
        →  递增站点版本戳（bump-version.py，重写各页内嵌版本号）
        →  部署 Cloudflare Pages（wrangler pages deploy）
        →  推送 GitHub（tools/sync-github.py，失败不阻塞主流程）
```

发布通道同时覆盖：企业微信群机器人推送 → 线上站点同步。

**关于缓存**：站点曾长期被浏览器/CDN 缓存困住，线上改动不生效。当前用三层对策根治：

1. HTML 全部带 `no-cache` 元信息；
2. 每次部署递增站点版本戳，写进所有页面的内嵌版本号与静态资源 query；
3. 页面内嵌「版本自愈」脚本——拉远端 `version.txt` 与当前页内嵌版本比对，不一致就换新 URL 重载。

## 技术实现

纯静态站点，**零构建步骤、零第三方运行时请求**：

- **零依赖前端** —— 原生 HTML/CSS/JS，无框架、无打包器、无 CDN 外链请求。
- **自托管字体子集** —— 标题用 Noto Serif SC 的「硅与海」三字形子集（1.6KB woff2），避免 Google Fonts 在国内阻塞渲染。
- **首屏视频降级策略** —— 默认只渲染 36KB 海报帧；仅当「桌面 + 网络良好 + 未开启减少动效」时才加载 1.1MB 背景视频，弱网/手机/`prefers-reduced-motion` 用户零视频流量，加载失败由 poster 兜底，不会黑屏。
- **无障碍** —— 遵循 `prefers-reduced-motion`，关闭入场动画与视频。
- **部署** —— Cloudflare Pages（项目名 `silicon-sea`），wrangler 增量上传，只传变化文件。

## 本地运行

```bash
cd ai-brief
python -m http.server 8080
# 打开 http://localhost:8080/
```

整站纯静态，任何静态服务器都能跑。注意 `version.txt` 的缓存自愈逻辑需要同源 HTTP 环境（`file://` 下 XHR 会被 CORS 拦掉，页面本身仍可正常阅读）。

## 部署

```bash
python tools/deploy-cloudflare.py            # 递增版本戳 + 部署
python tools/deploy-cloudflare.py --no-bump  # 只部署，不改版本号
```

需在 `tools/cloudflare-credentials.json` 放置 Cloudflare API Token 与 Account ID（该文件已 gitignore，不会入库）。
